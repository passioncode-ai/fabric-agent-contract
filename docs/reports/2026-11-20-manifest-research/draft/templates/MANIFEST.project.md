# The manifest of {{name}}, a project

`fabric-manifest/1` · rendered from fabric-agent-contract `{{contract}}` · declaration: `fabric.manifest.json`

These twelve articles hold for this project from its first commit, whatever it is built with. Technologies come and go;
the articles do not. Each article says the rule, then how it is met today (the binding), which may change by a
decision of the contract while the rule stays. Where this project does not meet an article yet, `fabric.manifest.json`
says `owed`, with the backlog row and the date. Do not edit this file by hand: it is rendered again from the contract
(`fabric-manifest/1`, proposed as DEC-0190; a draft until the contract accepts it).

## M-1. Agents first

Every function of this project is designed for agents from its first day. Anything a person can see or do in it (a
page, a button, a report, an export, an admin action), an agent can call with the same data, the same effect, the same
checks and the same record. An interface for people is built afterwards, only where a person needs it or the owner asks
for it, and each of its functions names the operation it serves. Only a human step (a sign-in, a one-time code, a
consent, a payment, a typed secret, spend above a limit) stays a person's. What this project knows (its documents,
decisions, specifications and code) other agents ask through its doors, never by reading its repository.

Binding today: an MCP surface with two doors, `search` and `execute`; for a project with nothing running, a cited search
over its knowledge served the same way.

## M-2. A brain from day one

This project keeps what it knows as linked data from its first commit: facts with the time they held and the time they
were recorded, their sources, the links between them, and a search that answers with citations. A regular sleep pass
consolidates it: it merges duplicates, links what belongs together, retires what stopped being true and records what it
learned. Its logs are structured, free of secrets and kept, so the brain learns from them.

Binding today: the knowledge layer `kb.*` (`kb.search`, `kb.map`), rebuilt on each commit, facts in two times, local
embeddings.

## M-3. Heals itself

Whatever this project runs (a service, a dashboard, a report, a scheduled job) notices its own failure and starts
healing by itself, with no person or command: it detects, diagnoses, repairs what it can repair safely, retries or
rolls back, and reports what happened: what broke, what was done, whether it worked. A person is called only at a
human gate. What cannot be
repaired, or may not be (money, deletion, publication, a human step), goes to the owning project or the person, once per
episode. A project with nothing running declares this article `not-applicable` with its reason.

Binding today: `agent-health/1` for what runs; each repair attempt recorded as `heal-attempt/1`; a report that refreshes
its data keeps the last good data with its date when a refresh fails.

## M-4. Organizations and projects stay apart

Every piece of data in this project belongs to one organization and one project. Data crosses that boundary only by an
explicit migration someone decided, never because a model asked for it. What has no owner is closed.

Binding today: the scope label `org/project`, one send gate, a transfer matrix.

## M-5. Secrets by name

A secret is named, never written: not in code, history, a command line, a link, a log, a prompt or memory. This project
names the slots it needs; the values come from the vault at run time.

Binding today: the vault by slot name (`<project>/<env>/<NAME>`).

## M-6. Foreign code through a fork

Code from someone else's repository is used through our own fork or a copy pinned to an exact commit, with its origin,
licence and our changes recorded beside it. It is never edited in place in a dependency folder or in a clone of someone
else's main line. A change meant for its authors goes to them as a proposal.

Binding today: the `forks` list of `fabric.manifest.json`, forks kept under the organization's account.

## M-7. The owner's decisions bind

The owner's decisions are written down with their words, the date, where they were said and their scope, in a register
that is only added to. Every agent working here decides every other open question itself: by the recorded decisions,
then the project's goal, then the safest reversible option, and writes its decision and reason where the work lives.
Only a human step waits for a person.

Binding today: the decision register named in `fabric.manifest.json`; an approval relayed with its four parts.

## M-8. Nothing that works is broken

A change is added beside what exists: a new version next to the old one, which keeps working. A regression is rolled
back first and fixed second.

Binding today: versioned revisions beside the old ones, a backlog and changelog line for every change.

## M-9. Every claim carries its proof

What this project states as true carries its evidence: a file and line, a command with its output, a test. What could
not be read is said to be unread, never shown as zero or as healthy.

Binding today: `degraded` in every answer, `unknown` never read as `ok`.

## M-10. Shares what it learns

What this project learns that others can use (a fix, a technique, a pattern, a better way) goes back to the shared base it was
built from, so our agents, our clients' agents and everyone who installs Fabric build on it. What is shared never
carries another organization's data or a person's: it is made anonymous on the device before it leaves. The shared base
is itself a brain: recorded, linked, updated and reused.

Binding today: the agents base's insights and contributions; `insight/1` once the contract publishes it.

## M-11. Updates arrive as a graph

This project learns of updates as linked knowledge, not as loose text: what changed, what it touches, what depends on
it, what was switched off. The machine's own coordinating agent reads that graph, sends verifiers to check which local
projects need the change, and applies it through the harness's own updaters, under M-8. This project can be updated, paused
or switched off, and says which version and which links it runs.

Binding today: the agents base's rollout ledger and update policy, `template-receipt.json`.

## M-12. Fits any setup

This project reads the setup it finds (the coding agents, the subscriptions and the keys of this computer, the person's
own or ours) and builds its solution for that setup, adapting when it changes. It never assumes one harness, one model
or one way of paying. A project with nothing running declares this article `not-applicable` with its reason.

Binding today: the contract's runners register; a subscription or tokens chosen per model's work.
